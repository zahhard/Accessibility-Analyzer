# تحلیلگر دسترس‌پذیری وب

ابزاری فارسی و راست‌به‌چپ برای ارزیابی اولیه‌ی دسترس‌پذیری صفحات وب بر پایه‌ی WCAG 2.2 AA، WAI-ARIA 1.2، Playwright و axe-core.

> این ابزار برای کشف سریع مشکلات رایج طراحی شده است و جایگزین ممیزی انسانی، تست کاربر یا تأییدیه‌ی حقوقی انطباق نیست.

## قابلیت‌ها

<ul dir="rtl" align="right">
<li>اجرای واقعی صفحه با Chromium در اندازه‌های موبایل، تبلت و دسکتاپ</li>
<li>بررسی مستقل حالت‌های روشن و تاریک با <code>prefers-color-scheme</code></li>
<li>اجرای axe-core با مجموعه‌قوانین WCAG 2.0، 2.1 و 2.2</li>
<li>قوانین تکمیلی برای زبان و جهت صفحه، عنوان، headingها، تصاویر، فرم‌ها، لینک‌ها، landmarks، iframe، جدول‌ها و viewport</li>
<li>امتیازدهی ۰ تا ۱۰۰ بر اساس شدت خطاها</li>
<li>گزارش فارسی شامل خلاصه‌ی وضعیت، نمودار شدت، جست‌وجو و فیلتر خطاها</li>
<li>نمایش selector، قطعه‌ی HTML، شرح خطا، راهکار اصلاح و لینک مرجع</li>
<li>کپی‌کردن HTML و selector برای استفاده در فرایند اصلاح</li>
<li>نمایش نکات مثبت شناسایی‌شده توسط آزمون‌های موفق</li>
<li>نمایش JSON خام خروجی <code>axe.run()</code> برای هر viewport و حالت رنگی</li>
<li>ثبت screenshot برای nodeهای خطادار و fallback از viewport در صورت شکست crop عنصر</li>
<li>تشخیص صفحه‌های ضدربات، Cloudflare و پاسخ‌های HTTP ناموفق</li>
</ul>

## روند تحلیل

تحلیل‌گر صفحه را با Chromium باز می‌کند و DOM نهایی پس از اجرای JavaScript را بررسی می‌کند. بنابراین نتیجه بر اساس محتوایی است که مرورگر واقعاً دریافت و رندر کرده است، نه فقط HTML خام پاسخ HTTP.

برای هر viewport انتخاب‌شده، دو context مستقل ساخته می‌شود:

1. حالت روشن با `colorScheme: "light"`
2. حالت تاریک با `colorScheme: "dark"`

در هر context، axe-core و قوانین سفارشی به‌صورت جداگانه اجرا می‌شوند. هر خطا در گزارش برچسب حالت رنگی خود را دارد. اگر سایت تم را فقط با کلیک روی دکمه یا مقدار `localStorage` تغییر دهد، شبیه‌سازی `prefers-color-scheme` به‌تنهایی آن تعامل را اجرا نمی‌کند.

## نکات مثبت و امتیازدهی

بخش «نکات مثبت» معیارهای موفق axe-core و قوانین سفارشی را نمایش می‌دهد. موارد تکراری بر اساس شناسه‌ی قانون ادغام می‌شوند و تعداد خام آزمون‌های موفق در فیلد `passesCount` نگهداری می‌شود.

در بخش «گزارش خام axe-core»، آرایه‌های `violations`، `passes`، `incomplete` و `inapplicable` برای هر ترکیب viewport و حالت رنگی نمایش داده می‌شوند. گزارش خلاصه‌ی برنامه از آرایه‌های `violations` و `passes` همین خروجی ساخته می‌شود.

امتیاز ۱۰۰ به این معناست که خطای قابل‌شناسایی توسط آزمون‌های خودکار پیدا نشده است؛ این امتیاز به‌تنهایی تضمین‌کننده‌ی دسترس‌پذیری کامل نیست. مواردی مانند معنادار بودن متن جایگزین، تجربه‌ی شناختی، کیفیت تعاملات کیبورد و درک‌پذیری محتوا همچنان به بررسی انسانی نیاز دارند.

## Screenshot خطاها

برای هر violation، اطلاعات زیر در گزارش نمایش داده می‌شود:

<ul dir="rtl" align="right">
<li>selector عنصر مشکل‌دار</li>
<li>قطعه‌ی HTML کوتاه‌شده</li>
<li>توضیح خطا و راهکار اصلاح</li>

اگر selector به‌دلیل DOM پویا، shadow DOM یا مخفی‌بودن عنصر قابل crop نباشد، screenshot همان viewport و حالت رنگی به‌عنوان تصویر جایگزین ثبت می‌شود.

## تشخیص Cloudflare و ضدربات

صفحه پیش از تحلیل، برای رندر client-side حدود ۱.۵ ثانیه زمان می‌گیرد و سپس حداکثر ۴ ثانیه برای آرام‌شدن شبکه منتظر می‌ماند. پس از آن عنوان و متن قابل‌مشاهده‌ی صفحه بررسی می‌شوند.

نشانه‌هایی مانند موارد زیر به‌عنوان صفحه‌ی چالش یا مسدودکننده شناسایی می‌شوند:

<ul dir="rtl" align="right">
<li><code>Just a moment</code></li>
<li><code>Checking your browser</code></li>
<li><code>Verify you are human</code></li>
<li><code>Ray ID</code></li>
<li><code>403 Forbidden</code></li>
<li><code>Access Denied</code></li>
</ul>

پاسخ‌های HTTP با وضعیت `401` و `403` نیز مستقیماً متوقف می‌شوند. در این وضعیت، برنامه از صفحه‌ی خطا screenshot یا score تولید نمی‌کند و خطای `ANTI_BOT_BLOCKED` برمی‌گرداند. ابزار Cloudflare را دور نمی‌زند؛ دسترسی IP سرور، user-agent و سیاست ضدربات سایت باید جداگانه بررسی شوند.

## تحلیل داخل مرورگر برای سایت‌های دارای 403

اگر سایت در مرورگر شما باز می‌شود اما سرور تحلیل‌گر پاسخ `403` دریافت می‌کند، می‌توانید axe-core را مستقیماً روی همان صفحه اجرا کنید. این روش از session و دسترسی واقعی مرورگر شما استفاده می‌کند و هیچ cookie یا کد خصوصی را به سرور تحلیل‌گر ارسال نمی‌کند.

۱. صفحه‌ی سایت را در مرورگر و در حالت مجاز خود باز کنید.
۲. فایل [`public/axe-browser.js`](public/axe-browser.js) را با یک وب‌سرور همین پروژه در دسترس قرار دهید یا محتوای آن را در DevTools Console همان صفحه اجرا کنید.
۳. پس از پایان تحلیل، پنل کوچک axe-core روی صفحه تعداد `violations`، `passes` و `incomplete` را نشان می‌دهد.
۴. با گزینه‌ی «دانلود JSON خام axe-core» خروجی واقعی `axe.run()` را ذخیره کنید.

این حالت فقط DOM و وضعیت فعلی صفحه را بررسی می‌کند. برای بررسی حالت تاریک، اسکریپت را یک‌بار در حالت روشن و یک‌بار پس از فعال‌کردن تم تاریک اجرا کنید.

## API

### درخواست

`POST /api/analyze`

<div dir="ltr" align="left">

```json
{
  "url": "https://example.com",
  "viewportIds": ["desktop"]
}
```

</div>

### پاسخ موفق

پاسخ شامل URL نهایی، عنوان صفحه، امتیاز، خلاصه‌ی خطاها، violationها، نکات مثبت، تعداد آزمون‌های موفق و گزارش هر viewport و حالت رنگی است.

### کدهای خطا

`INVALID_URL`، `BLOCKED_URL`، `RATE_LIMITED`، `ANTI_BOT_BLOCKED`، `PAGE_LOAD_FAILED`، `ANALYSIS_TIMEOUT` و `ANALYSIS_FAILED`.

جزئیات داخلی خطاها فقط در log سرور ثبت می‌شوند.

## امنیت و محدودیت‌ها

<ul dir="rtl" align="right">
<li>فقط URLهای <code>http</code> و <code>https</code> پذیرفته می‌شوند.</li>
<li>username و password در URL مجاز نیستند.</li>
<li>مقصدهای خصوصی باید فقط در محیط کنترل‌شده و با اجازه‌ی مالک سامانه تحلیل شوند.</li>
<li>rate limit فعلی حافظه‌ای است و برای اجرای چندنمونه‌ای در production مناسب نیست؛ برای این حالت Redis یا store توزیع‌شده پیشنهاد می‌شود.</li>
<li>نتیجه‌ی خودکار باید همراه با تست دستی صفحه‌خوان، کیبورد، بزرگ‌نمایی، کنتراست ادراکی و تجربه‌ی کاربر بررسی شود.</li>
</ul>
